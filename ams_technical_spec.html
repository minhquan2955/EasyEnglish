  • userIdref: users
  • studentCodeString, unique, indexed
  • dateOfBirthDate
  • genderenum: male | female | other

  • userIdref: users
  • studentIds[ref: students]

Academic
coursesCourse catalog
  • codeString, unique (e.g. IELTS-ADV)
  • nameString
  • categoryenum: ielts | toeic | kids | teens | business | comm
  • levelString (A1→C2)

  • classCodeString, unique, indexed
  • courseIdref: courses
  • teacherIdref: teachers
  • roomString
  • maxStudentsNumber
  • startDate / endDateDate
  • schedule{daysOfWeek[], startTime, endTime}

enrollmentsStudent↔Class bridge
  • studentIdref: students

  • statusenum: active | completed | dropped | transferred

  • classIdref: classes
  • teacherIdref: teachers

paymentsTransactions

2 — User Management
CRUD for all user types; parent↔student linking; account status control

POST/api/admin/teachers
POST/api/admin/students
POST/api/admin/students/:id/link-parent
PUT/api/admin/users/:id/status
3 — Academic Core
Course catalog CRUD; class creation with schedule pattern; student enrollment; schedule auto-generator service
GET/api/courses?category=&status=
POST/api/courses
POST/api/classes
POST/api/classes/:id/generate-schedules
POST/api/classes/:id/enroll
GET/api/classes/:id/students
4 — Scheduling
Query sessions by date/teacher/class; cancel, reschedule, substitute teacher assignment
GET/api/schedules?date=&teacherId=&classId=
GET/api/schedules/week?teacherId=&week=
PUT/api/schedules/:id
POST/api/schedules/:id/substitute
5 — Daily Operations
Bulk attendance marking per session; individual student attendance history; grade entry and retrieval
GET/api/attendance/session/:scheduleId
PUT/api/attendance/session/:scheduleId/bulk
GET/api/attendance/student/:studentId
POST/api/grades
GET/api/grades?studentId=&classId=
6 — Finance
Invoice generation from enrollment; payment recording; overdue detection via scheduled job
POST/api/invoices/generate
GET/api/invoices?studentId=&status=
PUT/api/invoices/:id/status
POST/api/payments
GET/api/payments?invoiceId=
7 — Notifications
In-app notification delivery; read state tracking; admin broadcast
GET/api/notifications?recipientId=&isRead=
PUT/api/notifications/:id/read
POST/api/notifications/broadcast

Key patterns + TTL
Refresh tokens TTL: 7 days
Stored on login; invalidated on logout or rotation. Enables stateless JWT access tokens (15 min TTL) without DB hit on every request.
auth:refresh:{userId} → tokenHash
Weekly schedule per teacher TTL: 1 hour
Teacher portal loads schedule on login and after every action. Cache the full week payload; invalidate on any schedule change affecting that teacher.
schedule:week:{teacherId}:{isoWeek} → JSON
Weekly schedule per student/parent TTL: 1 hour
Same pattern; cache invalidation triggered by class cancellation or rescheduling events.
schedule:week:{studentId}:{isoWeek} → JSON
Active course catalog TTL: 24 hours
Course list changes rarely. Used in enrollment dropdowns and public listing. Invalidate on course create/update/deactivate.
courses:active → JSON[]
Attendance session snapshot TTL: 2 hours
Teacher opens attendance panel → pre-load student list for that session. Warm on first load, serve from cache on re-open. Invalidate after bulk submission.
attendance:session:{scheduleId} → JSON
Rate limiting TTL: 15 min window
Protect /auth/login and /auth/forgot-password from brute-force. Use Redis INCR + EXPIRE pattern; block after threshold.
ratelimit:login:{ip} → count
